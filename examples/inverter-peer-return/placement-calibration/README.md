# Which point does the placement exporter use?

EasyEDA distinguishes the placement midpoint (**Mid X/Y**), the library origin (**Ref X/Y**) and the first pad (**Pad X/Y**). A pin-one direction alone cannot settle an offset on an asymmetric package. The separate workstation opened a catalog-only calibration board in **EasyEDA Standard 6.5.61 for Linux, Projects Offline mode**. From the PCB it used **Fabrication → Pick and Place File → Export**, in millimetres, with mirroring and panelized coordinates off. No buyer design was opened in EasyEDA or sent to a supplier.

The [original export](easyeda-original.csv) contains 14 parts with their public footprint geometry at zero rotation. The exporter writes UTF-16, tab-separated values rounded to 0.01 mm. All 14 virtual components have the expected footprint and first-pad coordinates; **in these particular cells** the exported Mid and Ref coincide at that precision. For the asymmetric C86206 regulator (X14), the exporter gives Mid and Ref **(1011.10, −763.92) mm** and pad 1 **(1005.70, −761.38) mm**. These are positions on the calibration card, not positions to enter in the buyer's CPL.

Run `python3 replay.py` here to verify the recorded cells and measurements. `python3 replay.py --make-pcb /new/path/reference.json` also reconstructs the exact test PCB from the public part records; the input digests must match. `--cache DIR` reads local copies instead. The source dimensions, part identities, URLs, distribution, export and calibration-file digests are in [reference.json](reference.json).

[EasyEDA Standard column definitions](https://docs.easyeda.com/en/PCB/Export-Coordinate/) · [Pro column definitions](https://prodocs.easyeda.com/en/pcb/export-pick-and-place-file/) · [JLCPCB’s EasyEDA BOM/CPL guide](https://jlcpcb.com/help/article/How-to-generate-the-BOM-and-Pick%26Place-file-from-EasyEDA). This measures a public CAD exporter for specific part footprints. It does not observe the production machine's feeder definitions, supplier acceptance or physical placement.
