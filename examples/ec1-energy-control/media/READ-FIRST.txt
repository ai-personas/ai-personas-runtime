EC1 RECEIVING DESK | Which kit is in this folder?

Use R2 for new log directories. Retain the earlier issue for reference only.
Do not open a submission to decide which it is. A name, icon, timestamp or
size alone cannot identify either kit.

1. Keep this trusted card and its identify.py separate from the copies.
   Leave the incoming folder unchanged while checking it. Open a terminal
   in the folder containing THIS handoff, not in the incoming folder.
2. Run one command, replacing the quoted example with the incoming folder:
   Windows (Python 3 launcher):  py -3 -I identify.py "D:\Desk copies"
   Linux/macOS (Python 3):       python3 -I identify.py "/media/Desk copies"
   No installation of packages, internet, extraction or submitted code is
   needed. The checker reads regular files including those in subfolders,
   regardless of extension. It does not write to the incoming folder.
3. Read each result by FULL PATH, then read the copy counts:
   R2        Matches the issue designated for new logs. Identify it for that
             job; do not run the submitted file during receiving. Multiple
             R2 paths are copies of the same issued bytes, not newer issues.
   EARLIER   Retain intact, marked earlier / not for new logs. Do not use it
             as a fallback even if it is the only recognizable kit.
   UNKNOWN   No listed match. Record path, byte count and SHA-256. Hold apart
             without opening or repairing it. Damage and unrelated content
             need not be distinguishable to make this decision.
   UNCHECKED Read failed, file changed, or path was skipped (e.g. link).
             Record the path/error. Hold unverified; no identity decision.
   R2=0      No VERIFIED current kit. Hold new-log intake; resume only with
             a verified R2. An unseen or unreadable file is not a substitute.
   EARLIER=0 Record earlier archive copy not verified; don't relabel another.
             Missing earlier bytes alone do not disqualify an R2 match.
   STOP      Folder could not be checked. Verify the folder path/access;
             do not interpret failure to scan as an empty folder.

Manual fallback | use a trusted local SHA-256 utility on the unopened file.
For example, Windows PowerShell: Get-FileHash -Algorithm SHA256 -LiteralPath 'D:\Desk copies\kit.zip'
On Linux: sha256sum -- '/media/Desk copies/kit.zip'
On macOS: shasum -a 256 '/Volumes/Desk copies/kit.zip'
Use actual paths. Compare ALL 64 hex digits (case does not matter) and the
file length in bytes, not allocated size. Repeat for every candidate path.
