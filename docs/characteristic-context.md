# Characteristic context: supply, influence and evidence

A valid profile, supplied characteristic text, observable behavior and useful
accomplishment are distinct claims. This page documents the current-context
invariant; it does not report a live persona evaluation.

## Character reaches the decision

Fresh setup retains each attributed seed. The initial persona decision authors
semantic OCEAN/VAD descriptions and exact own-voice fragment references. Custom
characteristics can be expressed in the seed and own-voice prose; they are not
additional model capabilities. A label such as intelligence does not change the
configured model, reasoning effort or demonstrated competence.

Accepted own voice is mandatory context. Optional characteristic fragments and
supporting assets remain separate, persona-selected sets. Ordinary requests also
supply the current need, accepted commitments and actual observations. The
provider serializer preserves current prompt text and appends it after any
explicitly selected provider history. Host contract text is the reusable
framing; persona-authored and retrieved content retains its own attribution in
the changing input. A later character adoption requires a fresh decision rather
than allowing old-character operations to run as if they used the new account.

There is no runtime formula translating openness into a number of searches,
reflection calls or tool invocations. There is no mandatory profession, leader,
reviewer or deliverable format. Initial instructions require preservation of
starting tendencies rather than converting every seed into an idealized common
collaborator. Structural validation does not establish semantic individuality.

## Nonblank resolved characteristic text

A nonempty stored file and a valid exact reference do not necessarily supply
characteristic prose. For example, a nonempty JSON file can contain an empty
string field, or a nonempty UTF-8 file can have a selected whitespace-only range.
The reference and its source hash can be valid while the selected body is blank.

`runtime::request_context::encode` now checks the resolved top-level qualified
context before either work-text or qualified-text sharing. Every entry whose
recorded scope is `fragments` must supply nonblank text. The check reads the
actual once-decoded field/range; it does not trim, rewrite, summarize, score or
replace the text. It applies to mandatory own voice, optional selected fragments
and fragment qualifications present in that current context. A diagnostic names
the exact offending reference. There is no minimum prose length or personality
score.

The resulting candidate context is rendered before an ordinary or character-only
Decision is committed. A blank projection therefore prevents adoption of that
candidate rather than persisting a nominal own-voice reference with no prose.
Existing exact-reference, complete-qualification and character-fence checks
remain in place. Earlier retained state with a blank selected fragment is held
with an exact-reference diagnostic rather than silently given a replacement
character. This patch supplies no migration or automatic recovery for such
state; a supported explicit correction must be established separately.

Empty supporting assets can be legitimate and are not rejected by this check.
Diagnostic reads of empty fields, historical inputs and their decoder remain
unchanged. This is not an erasure or a reinterpretation of earlier evidence.
The existing file layer already rejects `bytes_metadata` for fragment sources;
metadata-only references are not a newly discovered character-supply route.

Nonblank text is necessary but not sufficient. Generic or contradictory prose
can still be nonblank. This invariant is not a semantic validator, a claim that
the model used the text, or proof of improved work.

## Continuation stays a persona decision

Each persona chooses Immediate, timed reconsideration, a registered wait, Pause
or Stop under the actual work state. A peer stopping does not require another
participant to stop. A message or child result does not silently restart a
stopped participant, accept responsibility, or establish completion. Work-wide
user pause/cancel controls remain separate. A completion record and an authored
sufficiency account are not interchangeable.

Current parent participants can discover admitted immediate-child requests with
actual requester attribution. Artifact and result bodies still require useful
reads or explicit next-context selection. Saving supporting notes, having five
profiles or removing spending quotas does not itself demonstrate sustained
engineering accomplishment.

## Verification boundary

Mechanical checks should exercise a nonempty file selecting an empty JSON
string, a whitespace-only UTF-8 range, Unicode whitespace, nonblank own voice,
empty supporting assets and historical diagnostic reads. A complete synthetic
Runtime exercise should verify rollback of the candidate Decision and retention
of the previous accepted character. A later valid projection must be admissible
without rewriting history. Fixtures and validation logs belong outside the
repository, as required by CONTRIBUTING.md.

Actual character influence needs a separately authorized model evaluation with
exact supplied contexts, observable questions/actions/tool results, appropriate
outcomes and comparison conditions. Different names, profile descriptions,
accepted edits, self-reports and call counts alone do not establish that benefit.
